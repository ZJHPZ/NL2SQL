# M7：数据开发工作台（多项目 / 可视化数据源 / SQL 任务）

> 本文件记录 M7 的设计、实现与验收。一句话：把「单库问答工作台」扩展为
> 「多项目 + 任意数据库连接 + SQL 任务（可生成/修改/版本化）+ 智能体读取项目信息」的
> 数据开发工作台；**任务只写项目自己的任务库，不写业务库数据。**

## 1. 范围与边界

| 需求 | 做法 | 不做什么 |
|---|---|---|
| 多项目 | `projects/<pid>/`（`project.toml` + `secrets.json` + `state/`），每个项目一个独立引擎 | 不做多租户/远程共享；无项目级用户体系 |
| 接真库 | 复用已有 SQLite / MySQL / PostgreSQL 适配器 + 新增 **JDBC 泛用桥**（Java 17） | 不替用户装数据库；驱动 jar 按需下载 |
| 可视化连接 | Web「项目」页：选类型、填参数、**测试连接**、保存口令、浏览表结构 | 不做连接池/主从/代理 |
| 增删改查/数据开发 | **任务 artifact**：任务=名字+只读 SQL+说明+版本历史；agent 生成/修改任务并加 `-- ai修改，…` 注释 | **任务不写业务数据**；不自动执行、无调度器；写业务库暂不支持 |
| 智能体读项目信息 | `project_brief` 常驻注入 system prompt + `project.info` 工具 | 不把口令写进 Prompt/工具结果（`_project_info()` 明确排除） |
| 实际代码操作能力 | 落在受限产物（SQL 任务）上：`task.create/task.update` 只写任务库 | 不提供任意 Python 执行（RCE 风险） |

安全事实：`read_only=True` 仍是默认；`guard` 只放只读单语句；任务 SQL 在**创建/修改/执行**三处各校验一次
（单语句 + 只读）；执行默认由用户点「运行」，执行结果沿用九态契约。写操作能力 `source.write`
仍只是声明、无实现（延续 docs/03 的边界）。

## 2. 核心新增（`nl2sql/`）

### 2.1 `nl2sql/tasks.py` —— 任务库（独立 SQLite）

- `Task`：`task_id / project_id / name / description / sql / revision / enabled / tags /
  created_by / updated_by / created_at / updated_at / last_run_at / last_status / source_id`
- `TaskRevision`：每次修改追加一行版本（`PRIMARY KEY(task_id, revision)`），`author ∈ {user, ai}`，
  支持从任意旧版本**回滚**（回滚也是"生成新版本"，历史只增不改）
- `validate_task_sql()`：非空、≤20000 字符、**恰好一条**语句、**只读**（SELECT/WITH/EXPLAIN）
- `stamp_ai_comment()`：AI 修改 SQL 时在末尾追加 `-- ai修改，YYYY-MM-DD HH:MM`（可带备注），
  满足"AI 修改要留痕"的诉求
- 存储路径：`<project>/state/tasks.db`；默认项目不启用任务库（保持旧行为），
  `NL2SQL_TASKS_ENABLED=1` 时默认项目也启用
- **任务库与业务库物理隔离**：任务库是项目自己 `state/` 下的文件，业务库连接是只读的

### 2.2 `nl2sql/agent/tool_tasks.py` —— 智能体的项目/任务工具

| 工具 | 能力 | 说明 |
|---|---|---|
| `project.info` | `project.read` | 当前项目名/描述/数据源摘要/任务统计（**不含口令**） |
| `task.list` / `task.get` | `task.read` | 列出/读取任务与版本历史 |
| `task.create` | `task.write` | 新建任务（写任务库，author=ai） |
| `task.update` | `task.write` | 修改任务；改 SQL 时自动加 `-- ai修改，…` 注释并生成新版本 |

工具只在任务库启用时条件注册；缺能力/缺资源时返回可行动的 `ToolResult`（工具契约禁止抛异常）。

### 2.3 `project_brief` 常驻注入

`AgentCore` 新增 `project_brief`：每轮拼在 system prompt 的 schema_brief 之前，内容 = 项目名/描述/
数据源/任务统计/任务操作规范（创建任务只保存 SQL、不自动执行、不写业务数据）。
小、稳定、比让模型多调一轮 `project.info` 省一次调用。链路：
`api._project_brief()` → `make_runtime(..., project_brief=...)` → `AgentRuntime/LangGraphRuntime`
→ `AgentCore._ask_model`；`apply_runtime_settings()` 可热更新。

### 2.4 配置

- `NL2SQLConfig.project_id/project_name/project_description/task_store_path/credentials/semantic_mode`
  （`credentials` 是壳在内存注入的 `source_id → {"password": ...}`，不落 TOML）
- `semantic_mode`：`auto`（有 dbt 指标文件就用，否则内置黄金集——旧行为）/ `dbt`（必须有指标文件）/
  **`none`（不装语义层：接任意业务库，agent 直接读库表写只读 SQL）**
- `AgentConfig.capabilities` 默认追加 `project.read / task.read / task.write`
- `add_jdbc(jdbc_url, driver_class, jar_paths, ...)` + `SourceConfig.validate()` 的 jdbc 分支
- `connect()` 把 `credentials` 传给 `build_adapter`（口令只从内存/环境/密钥文件来，不进 TOML）

## 3. JDBC 泛用适配器（`nl2sql/sources/`）

- `jdbc.py`：`JdbcAdapter` 实现 `SourceAdapter` 协议（test_connection / introspect / execute / explain / close），
  懒启动、复用同一个 Java 进程、`limit+1` 探测截断、单元格统一转字符串（NULL 保留 None）
- `jdbc_bridge/JdbcBridge.java`：长驻桥，stdin/stdout 单行 JSON 协议；**只读防线**：拒绝写语句/
  多语句/锁定读（在 Java 侧再校验一次，不依赖 Python 侧）
- `drivers.py`：驱动注册表（sqlite / mysql / postgresql / mssql），固定版本 + Maven Central 下载 +
  附加依赖（如 sqlite-jdbc 的 slf4j-api）+ `driver_status()` 报告
- 依赖 Java 17（`java`/`javac` 在 PATH 或 `NL2SQL_JAVA`/`NL2SQL_JAVAC`）；缺环境时测试**跳过并明示
  "未跑 ≠ 通过"**

## 4. Web 后端（`apps/web/backend/`）

| 文件 | 内容 |
|---|---|
| `projects.py` | `ProjectStore`（TOML 读写、口令分离到 `secrets.json`、slug 校验、数据源校验）；`ProjectHub`（懒加载/缓存每项目引擎、`X-Project-Id` 路由、默认项目=环境变量引擎、失败进 warnings、`invalidate` 热更新） |
| `routers/projects.py` | 项目 CRUD、数据源 CRUD、`/sources/test`（永远 200 + `{ok, message, dialect, elapsed_ms, tables}`）、表结构、快照、JDBC 驱动列表/下载 |
| `routers/tasks.py` | 任务 CRUD、版本历史、回滚、**手动执行**（复用 `/api/execute` 的只读防线，九态返回） |
| `deps.py` | `get_project_entry` / `get_engine` 读 `X-Project-Id`（未知项目 404、引擎失败 503）；保留旧 `EngineHolder` 兼容 |
| `main.py` | lifespan 建 `ProjectHub`；注册 projects/tasks 路由 |

前端（`apps/web/frontend/src`）：顶部导航「问答 / 项目 / 任务」+ 项目切换器（全局 `X-Project-Id`）；
项目页 = 项目列表 + 数据源向导（含测试连接、JDBC 驱动下载、表结构预览）；任务页 = 任务列表 +
SQL 编辑/版本历史/回滚/运行 + 结果表。

## 6. 使用（最小步骤）

```bash
# 1) 启动 Web 工作台（默认连 golden 演示库；无 Key 时 agent 自动降级为规则规划器）
#    前端先构建一次：cd apps/web/frontend && npm install && npm run build
uvicorn apps.web.backend.main:app --port 8000
#    打开 http://127.0.0.1:8000

# 2) 打开 http://127.0.0.1:8000 → 顶部「项目」→ 新建项目
#    - 语义层选「无（直接用库表）」即可接任意业务库
#    - 数据源选 SQLite（填路径）/ MySQL / PostgreSQL / JDBC（填 JDBC URL + 驱动类）
#    - 「测试连接」→ 保存 → 项目切换器选中它

# 3) 顶栏「任务」→ 新建任务，或直接问 agent：
#    「为我创建一个任务，查询 fact_order 表里已支付订单的渠道金额」
#    「这个任务里我要把金额改成按渠道分组的实收金额，帮我改一下」
#    agent 会调用 task.create / task.update，SQL 末尾自动带 `-- ai修改，…`

# 4) 点「运行」执行任务（只读）；「任务」页可看版本历史并回滚

# CLI 验证 JDBC（可选，需要 JDK 17）
python tests/test_m7_jdbc.py
python tests/test_m7_projects_api.py
```

## 7. 已知限制

1. **JDBC 需要 JDK 17**（编译桥、运行驱动）；首次使用要联网下载驱动 jar（Maven Central）。
2. 受限沙箱里 `tasklist` 看不到 java 进程（进程回收用例在沙箱中退化为信息性检查）。
3. **前端构建需要在普通 shell / 放宽沙箱执行**：受限沙箱禁止 esbuild 的带管道子进程（`spawn EPERM`）。
4. `secrets.json` 是本地文件（不进 git、接口不回传口令），**没有加密**；生产使用需换密钥管理。
5. 任务默认**不自动执行、无调度**；"是否执行由用户判断"。写业务库（`source.write`）仍未实现。
6. 默认项目（环境变量连接）默认不启用任务库；需要时设 `NL2SQL_TASKS_ENABLED=1`。
7. 任务 SQL 目前无参数模板/调度依赖；每项目一个数据源为主，多源可保存但执行按任务 `source_id` 路由。

## 8. 与旧能力的关系（兼容性）

- **默认项目零变化**：不设 `NL2SQL_PROJECTS_DIR` 时行为与 M5 一致（环境变量引擎、无任务库）。
- 所有旧路由（`/api/query`、`/api/execute`、`/api/admin/*`…）保持；只是新增了 `X-Project-Id` 寻址。
- 任务/项目相关的 agent 工具**条件注册**：没有任务库时工具清单与旧版一致（零技能同等原则）。
- 语义层 `semantic_mode` 默认 `auto`，旧配置的行为不变。
