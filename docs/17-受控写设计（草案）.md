# 受控写设计（草案）

> 状态：草案，待评审。目标库先定「**自己的测试库**」（SQLite / 自建测试 MySQL、PG）。
> 现有只读防线（`nl2sql/guard/__init__.py` 只读 + 单条 + LIMIT + 超时；适配器连接只读；
> `apps/web/backend/routers/tasks.py` 的 `_execute_readonly`）**保持不动**，写入走独立通道。

## 1. 边界：只做「受控写」，不做 SQL 控制台

**做**：
- 单表 `INSERT (cols) VALUES (...)` / `UPDATE ... SET ... WHERE ...` / `DELETE FROM ... WHERE ...`；
- 只能由「写任务」在任务工作台里执行；两阶段：**预演（dry-run）→ 人确认 → 提交**；
- 项目级显式开启写权限，默认关闭；读写账号分离。

**不做**（本期）：
- DDL（建表 / 改表 / 索引）、`TRUNCATE`、`DROP`；
- 多语句、子查询写、`INSERT ... SELECT`、无 WHERE 的 `UPDATE/DELETE`、`WHERE 1=1`；
- 跨项目 / 跨库写；问答链路（`/api/query`、`/api/execute`、随行智能体）永远只读；
- 定时写 / 批量写 / 外部调用写接口。

## 2. 安全模型（四层，缺一不可）

1. **语句层（新 WriteGuard）**：单语句；首关键字 ∈ `INSERT/UPDATE/DELETE`；单目标表；
   UPDATE/DELETE 必须有非恒真 WHERE（至少一个列条件）；影响行数上限（默认 100，可配）+ 超时；
   拒多语句、注释注入、`RETURNING` 之外的怪写法。
2. **执行层（两阶段）**：预演在事务里执行 → 记录影响行数与命中的前 N 行 → `ROLLBACK`；
   用户点「确认提交」后重新校验行数上限，再事务执行并 `COMMIT`，任何异常自动回滚。
3. **账号层（读写分离）**：写连接用独立账号/独立连接参数；MySQL/PG 只授目标库目标表写权限；
   SQLite 打开可写连接但仅允许 WriteGuard 通过的语句；JDBC 桥单独维护可写实例（默认不放行）。
4. **审计层**：写操作落项目任务库 `audit` 表——谁 / 项目 / 任务 / 版本 / SQL / 预演行数 /
   确认时间 / 提交结果 / 影响行数 / 失败原因。审计不可改、不随任务删除。

## 3. 接口与数据结构（草案）

- 任务：新增 `kind: 'read' | 'write'`（写任务仍保留 SQL 文本 + 版本历史）。
- 端点：
  - `POST /api/projects/{pid}/tasks/{tid}/write/dry-run` → `{dry_run_id, rows, diff, sql}`
  - `POST /api/projects/{pid}/tasks/{tid}/write/commit` → 需 `dry_run_id` + 显式 `confirm: true`
  - 只读任务继续走现有 `run`。
- 项目设置：`data_write: { enabled: bool, source_id: str, max_affected: int }`（默认 `enabled=false`）。
- 任务库新增 `audit` 表：`id, project_id, task_id, revision, actor, sql, dry_rows, committed_rows,
  status, error, created_at`。
- Guard 扩展：`WriteGuard` 独立于现有 `Guard`（读路径零改动）；两者共用 `split_statements`、
  `is_read_only` 等 token 工具。

## 4. UI 流程

- 编辑器：写任务类型 badge 显示「写入」；运行按钮改为「预演写入」。
- 预演后底部面板：影响行数 + 前 N 行 diff 表 + 「确认提交」朱红按钮（文案含行数，如
  「确认提交：将更新 37 行」）；提交后显示结果并写审计；未预演不允许提交。
- 项目设置：「允许写入」开关 + 选择写数据源 + 影响行数上限；开启时要求输入项目名二次确认。

## 5. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 预演与提交之间数据变化 | 提交前重新校验行数上限；按任务串行化加锁 |
| 模型生成错误 SQL | 预演 diff 必须人看；默认不信任模型自动提交 |
| 权限扩散 | 写账号只授目标表；默认关；审计必开 |
| 回滚需求 | 预演即事务回滚；提交后保留补偿 SQL（首期测试库先落快照/导出） |
| 后续接生产库 | 审批流 + 时间窗 + 双人确认（P2，不在本期） |

## 6. 分阶段与验收

- **P0（本期）**：本设计评审通过；测试库打通 dry-run / commit / audit 三条链路。
- **P1**：项目设置开关 + 工作台两阶段 UI + 审计查询页。
- **P2**：MySQL/PG 写账号与 DDL 审批（暂不做）。

验收（测试库）：
1. 100 行内 `UPDATE` 可预演、看 diff、提交、审计可查；
2. 无 WHERE 写、多语句、DDL、超行数上限被拒（返回明确原因）；
3. 未开启写权限的项目，写接口 403；问答链路对写语句仍一律拒绝；
4. 提交失败自动回滚，任务 SQL 与版本历史不受影响。
