# 跨期对比

## 何时用

问句把**两个时间窗**并排问："本月和上月分别卖了多少""同比/环比增长多少"
"上半年和去年下半年比呢"。注意：这是两个时间窗，不是"一段时间内按月看趋势"。

## 步骤

1. **先确认指标口径**。用语义层里已注册的口径，不要凭名字猜
   （例如"实收金额"通常排除了未支付和退款）。拿不到口径就如实说缺什么。
2. **两个时间窗各自取数**，再并排成列。
   - 规则规划器通常把时间窗做成列（pivot），或做成"窗口"维度；
   - **不要把两个时间窗塞进同一个过滤条件**。列已经把时间写死了，
     再叠一个时间范围只会命中其中一个窗口，另一列恒为 0 / 空——而且不报错。
3. 用户若问"增长了多少"，在结论里补**变化量**与**变化率**，
   不要只给两列数字让他自己算。
4. 回答里写清：口径、两个时间窗的边界（含首尾日）、以及数据是否覆盖完整。
   某个窗口没有数据时如实说"该时间段没有数据"，不要用相邻月份顶替。

## 若能力不足

- 语义层没有这个指标/时间窗表达不了：换一种能表达的做法（例如分别查两次再合并），
  或**如实报告缺什么**。
- 若只能用裸 SQL：说明为什么语义层表达不了，并在回答里**披露公式与时间窗边界**。
- 不要为了"凑出两列"而编造另一列的数字。

## 反面例子

- 把"本月和上月"写成"月份 in (本月, 上月)"：那会退化成**一行**（或两行明细），
  不是两列对比。
- 把时间范围同时写进全局过滤和窗口列：另一列被切掉，结果看起来"合理"但是错的。
- 只给两个数字、不说明口径与边界：用户无法判断这两个数能不能比。
